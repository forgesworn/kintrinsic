# Kintrinsic (charter)

Kintrinsic is a libre, self-hosted digital wardship system: a guardian grants
scoped, revocable screen-time, app, content and comms permissions to a child's
devices, signed with the family's own Nostr keys and enforced on-device. This
repository is a monorepo: an Android Device Owner enforcer, a Linux warden
(`charterd`), a guardian PWA, the wire contract, and the `@forgesworn/charter`
consumer SDK. Code, daemons and identifiers keep the working name `charter`
(the product name is Kintrinsic).

## Root TS SDK (`src/`, package `@forgesworn/charter`)

| Command | Purpose |
|---|---|
| `npm ci` | Install dependencies |
| `npm run build` | Compile with `tsc` to `dist/` |
| `npm test` | Run the vitest suite |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | `eslint src/` |
| `npm run lint:fix` | `eslint src/ --fix` |

## Rust workspaces

`core/` and `linux/` are separate Cargo workspaces (`core/Cargo.toml`,
`linux/Cargo.toml`), each pinning its toolchain in `rust-toolchain.toml`. From
inside either directory:

| Command | Purpose |
|---|---|
| `cargo fmt --all --check` | Format check |
| `cargo clippy --all-targets -- -D warnings` | Lint |
| `cargo test --workspace` | Run tests (default/mock features) |

`linux/` also has a `real` feature (the actual enforcement runtime, zbus and
rustls) and `core/crates/charter-sys` a `real-relay` feature (live-websocket
relay IO); both are excluded from the default test run and must be built and
tested explicitly, e.g. `cargo test -p charterd --features real`.

## Layout

- `spec/contract.md`: the Nostr wire protocol (clauses, grants, deny and audit
  shapes). Source of truth for message shapes.
- `core/`: shared Rust crates (crypto, verification, transport, schedule,
  content, webpolicy) used by both the Linux warden and, via JNI, Android.
- `linux/`: the `charterd` warden, tray, lock UI and `.deb` packaging.
- `android/`: the ward enforcer (`app`) and guardian carrier (`carrier`).
- `apps/`: the guardian PWA (`charter-app`) and related console/tray apps.
- `src/`: the consumer SDK (`@forgesworn/charter`), with `schedule/`,
  `pairing/` and `evaluator/` subpath exports plus a top-level barrel.
- `test/`: vitest suites for the consumer SDK.
- `docs/`: `integrating.md` (consumer integration guide) and other docs.
- `scripts/`: vector generation and release helpers.

## Conventions

- British English in prose and comments.
- Wardship terminology: guardian/ward, not "parent/child controls"; clause,
  not "setting"; warden, not "agent" or "controller". See the README lexicon
  table.
- The wire contract (`spec/contract.md`) is the source of truth; the TS SDK
  and the Rust crates must agree with it and with each other. Golden vectors
  in `core/crates/charter-testkit/vectors/` are generated by
  `scripts/gen-schedule-vectors.mjs` and `scripts/gen-nostr-vectors.mjs` and
  are checked for drift in CI: do not hand-edit them.
- Pairings and cached clauses are per-device by design; do not add
  cross-device sync to `createPairingStore`.

## Common pitfalls

- `core/` and `linux/` are independent Cargo workspaces, not one workspace:
  run `cargo` commands from inside the relevant directory.
- `cargo test --workspace` in `linux/` does not compile `runtime.rs` (the
  enforcement loop and on-display lock): that code is behind the `real`
  feature and needs `cargo test -p charterd --features real` to exercise.
- Consumer apps must go through the NIP-46 bunker transport; do not read a
  dependant's IndexedDB pairing store directly.

## Verifying a change

- TS SDK: `npm run lint && npm run typecheck && npm run build && npm test`.
- Rust workspace: from `core/` or `linux/`, `cargo fmt --all --check &&
  cargo clippy --all-targets -- -D warnings && cargo test --workspace`.
- If a change touches clause schemas or the wire contract, regenerate vectors
  with `node scripts/gen-schedule-vectors.mjs` and
  `node scripts/gen-nostr-vectors.mjs` and check for an unexpected diff.
